# Renoly v2 前端規格

文件狀態：Draft v1  
適用範圍：內部 Web App / PWA、技師 PWA、客戶 LINE Web 頁  
相關文件：[產品規格](./product-spec.md)、[使用者旅程與驗收條件](./user-journeys.md)

## 1. 前端目標

Renoly v2 前端服務三種店內角色與一種外部使用者：

- owner：掌握營運、核准報價、管理設定與成員。
- dispatcher：處理進件、報價草稿、排程、通知與追蹤。
- technician：在手機上查看個人工單、更新狀態與留下現場紀錄。
- customer：不安裝 App、不建立後台帳號，從 LINE 的安全連結完成單次任務。

前端成功的判準：

- 新使用者不需教學即可理解「現在在哪個階段、下一步是什麼」。
- owner／dispatcher 能在 30 秒內找出待處理案件與責任人。
- technician 從開啟工單到完成到場打卡，主要操作不超過 3 次點擊。
- customer 可在 LINE 內建瀏覽器完成表單、報價確認與完工簽認。
- 每個異常狀態都告訴使用者「發生什麼、資料有沒有保存、接下來能做什麼」。

## 2. 前端表面與路由原則

本文件的路由為 v2 目標資訊架構，可在實作時使用 Next.js route group，但使用者可見 URL 與頁面名稱應保持語意一致。

### 2.1 店內工作台

路徑前綴：/app

適用角色：owner、dispatcher；technician 依權限只看精簡內容。

主要功能：工作台、接案匣、案件、報價、排程、客戶、收款、回訪、通知與設定。

### 2.2 技師 PWA

路徑前綴：/app/today、/app/work-orders

適用角色：technician；owner／dispatcher 可切換為預覽但不改變自身權限。

主要功能：今日任務、工單詳情、導航、狀態、檢查表、照片、異常、追加草稿與完工。

### 2.3 客戶頁

路徑前綴：/request、/public

適用角色：持有有效安全連結的客戶。

主要功能：填寫需求、查看報價、確認時段、確認追加、簽認完工、查看付款與服務摘要。

客戶頁沒有全域帳號導覽，不顯示 Renoly 後台，不暴露 organization id、case id 或可推測的流水號。每個頁面只提供當下任務與店家聯絡入口。

## 3. 全域資訊架構

### 3.1 owner／dispatcher 手機底部導覽

固定五項：

1. 工作台：今日摘要與待辦。
2. 接案匣：新需求與需補資料案件；顯示未處理數 badge。
3. 案件：所有進行中與歷史案件。
4. 排程：日／週工單與技師負載。
5. 更多：客戶、收款、回訪、通知、團隊與設定。

規則：

- 當前項目同時使用圖示、文字與選取樣式。
- badge 最大顯示 99+，螢幕閱讀器需讀出完整數量。
- 開啟鍵盤、相機、全螢幕編輯器或客戶預覽時可暫時隱藏底部列。
- iOS safe area 必須保留，內容不得被底部導覽遮住。

### 3.2 owner／dispatcher 桌面導覽

左側欄顯示：

- 工作台
- 接案匣
- 案件
- 排程
- 客戶
- 收款
- 回訪
- 通知
- 設定

側欄可收合；案件詳情與排程可使用主內容＋右側 contextual panel。桌面版增加資訊密度，但功能和手機版相同。

### 3.3 technician 導覽

手機底部固定三項：

1. 今日
2. 任務
3. 我的

technician 不看到工作台營運數字、全店客戶清單、收款總覽、團隊設定、成本或毛利。若沒有指派任務，「今日」只顯示明確空狀態與聯絡派工人員按鈕。

### 3.4 全域快速動作

owner／dispatcher 的主要新增按鈕可開啟動作面板：

- 建立案件
- 建立客戶
- 建立工單
- 建立報價

動作面板需保留來源上下文。例如從客戶頁開啟時預先帶入客戶，從案件頁開啟時預先帶入案件。

## 4. 共通版面與互動規則

### 4.1 頁面骨架

每個內部頁面依序包含：

1. 頂部列：返回、頁名、狀態／未同步提示、主要更多選單。
2. 摘要區：關鍵狀態、下一步、時間、責任人。
3. 主內容：列表、表單或流程內容。
4. 固定動作區：當頁唯一主要動作；不可同時出現兩個視覺權重相同的 CTA。
5. 底部導覽：僅頂層頁面顯示。

### 4.2 文字與名詞

對使用者統一使用：

- 「案件」：從詢問到結案的整體紀錄。
- 「工單」：一次現場任務。
- 「報價」：客戶可確認的價格版本。
- 「追加／追減」：原報價外的金額變更。
- 「派工」：將工單指派給技師與時段。
- 「現場紀錄」：檢查表、照片、備註與事件。
- 「簽認」：可稽核的客戶確認紀錄。

不要在 UI 混用 lead、request、project、job、work order 等內部英文名。

### 4.3 狀態呈現

狀態元件必須包含文字，不能只用顏色。

建議語意色：

- 中性灰：尚未開始、草稿、未排程。
- 藍色：等待外部回覆、已排程、已送出。
- 橘色：需要店內行動、待核准、即將到期。
- 綠色：已接受、已完工、已付款。
- 紅色：失敗、逾期、衝突、取消。
- 紫色：保固、回訪或特殊流程。

狀態選單只能顯示允許的下一步；高風險回退需二次確認並要求原因。更新成功後在畫面上顯示時間與操作者。

### 4.4 日期、時間與金額

- 金額：NT$ 12,500；列表可省略小數，計算仍保留正確精度。
- 日期：2026/07/16；同年度的近期列表可顯示 7/16（四）。
- 時間：14:30；時段顯示 14:00–16:00。
- 相對時間只作輔助，例如「12 分鐘前」，旁邊或 tooltip 保留絕對時間。
- 時區固定顯示組織時區，預設 Asia/Taipei。

### 4.5 搜尋與篩選

- 搜尋支援客戶姓名、電話末碼、地址、案件編號與標題。
- 輸入 300–500 ms 後搜尋，送出中的文字不可遺失。
- 篩選器以 bottom sheet（手機）或 popover（桌面）呈現。
- 已套用的篩選需可見並可逐一清除。
- 返回列表時保留搜尋、篩選、捲動位置與分頁。

## 5. 身分驗證與導入頁面

| 路由 | 頁面 | 角色 | 主要功能 | 特殊狀態 |
|---|---|---|---|---|
| /login | LINE 登入 | 全部店內角色 | 說明用途、LINE 登入、隱私與服務條款 | LINE SDK 載入失敗、使用者取消、瀏覽器不支援 |
| /app/onboarding | 建立／加入店家 | owner 或受邀成員 | 建立組織、接受邀請、判斷已有組織 | 邀請失效、已加入、無權加入 |
| /app/onboarding/template | 選擇產業模板 | owner | 選冷氣／水電／抓漏防水／其他，預覽預設流程 | 儲存失敗時保留選擇 |
| /app/onboarding/basics | 店家基本設定 | owner | 店名、Logo、聯絡方式、服務區域、工作時間 | Logo 上傳失敗可略過 |
| /app/onboarding/team | 邀請成員 | owner | 邀請 dispatcher／technician，可稍後完成 | 重複邀請、邀請額度、傳送失敗 |
| /app/onboarding/catalog | 服務與價目 | owner | 使用模板項目、編輯售價／成本、略過 | 無預設項目、匯入錯誤 |
| /app/onboarding/line | LINE 串接 | owner | 顯示串接步驟、測試連線、可先用手動分享模式 | 權限不足、驗簽失敗、token 失效 |
| /app/onboarding/done | 導入完成 | owner | 顯示完成項目、建立第一筆示範／真實案件 | 尚未完成的必要設定 |

導入規則：

- 進度可保存並在下次登入繼續。
- 不要求一次完成非必要串接；必填與可稍後設定需清楚區分。
- 示範資料必須明確標記，且可由 owner 一次移除。
- technician 接受邀請後直接進入「今日」，不經過店家設定。

## 6. 工作台與接案匣

### 6.1 工作台

路由：/app/dashboard  
角色：owner、dispatcher

內容順序：

1. 問候與今日日期。
2. 行動摘要：待回覆、待核准報價、今日工單、待收款、到期回訪。
3. 今日排程：依時間排序，顯示技師、客戶、地點、狀態與衝突。
4. 需立即處理：逾時未回、報價即將失效、延誤、上傳失敗、逾期款。
5. 四項 KPI：首次回覆、報價接受率、完工率、回訪轉單率。

主要動作：建立案件。

狀態：

- 全新店家：顯示 3 步開始卡（設定服務、建立案件、邀請技師），不顯示一排 0%。
- 今日無工作：顯示下一個排程與「查看待處理案件」。
- 部分 widget 載入失敗：其他內容仍可用，失敗區塊可單獨重試。
- KPI 資料不足：顯示所需條件與可採取行動。
- 跨日未重新整理：回到前景時更新日期與資料。

### 6.2 接案匣

路由：/app/inbox  
角色：owner、dispatcher

功能：

- 分頁：待處理、待補資料、等待客戶、全部。
- 卡片顯示來源、收到時間、客戶、服務類型、地址區域、照片數、摘要與負責人。
- 快速動作：指派、標記已回覆、要求補資料、合併重複、封存垃圾訊息。
- 依最久未回覆排序；可按來源、服務、區域、優先度、負責人篩選。
- 開啟項目使用 detail sheet，桌面可在右欄處理。

主要動作：人工建立案件。

狀態：

- 無待處理：說明新的 LINE／表單需求會出現在此，提供測試表單連結。
- 疑似重複：顯示比較，不自動合併。
- webhook 來源異常：頁首顯示影響範圍與設定入口。
- 內容可能有害／無法解析：以純文字安全顯示並允許人工處理。
- 多人同時領取：第二位使用者看到已由誰處理，可選擇重新指派。

### 6.3 進件詳情

路由：/app/inbox/[id]  
角色：owner、dispatcher

功能：

- 顯示原始需求、結構化摘要、客戶、聯絡方式、地點、設備與照片。
- 顯示來源與可稽核的原始事件，不把 AI 摘要當唯一資料。
- 編輯服務類型、優先度、責任人、下一步與內部備註。
- 動作：建立／連結客戶、建立案件、要求補資料、標為不適用、合併重複。
- 對客訊息送出前提供完整預覽。

狀態：

- 客戶資料不完整：缺少欄位集中列出。
- 已轉成案件：M3 顯示資料庫讀回的案件編號並停用再次轉換；M5 案件工作台完成前不渲染死連結，完成後才把主要動作改為「前往案件」。
- 原始照片尚在搬移：顯示處理中，不允許誤認遺失。
- 摘要失敗：仍顯示原始內容並允許手動整理。

## 7. 案件頁面

### 7.1 案件列表

路由：/app/cases  
角色：owner、dispatcher

功能：

- 預設分頁：進行中、等待客戶、待收款、已結案。
- 卡片／表格顯示案件標題、客戶、區域、模板類型、階段、下一步、負責人、最近更新。
- 搜尋與多條件篩選；可儲存常用檢視（P1）。
- 可從列表快速改責任人與下一步日期。

主要動作：建立案件。

狀態：

- 無案件：可選擇從範例建立或建立真實案件。
- 搜尋無結果：保留搜尋詞，提供清除篩選。
- 離線：顯示最近快取資料與最後同步時間，禁止無法安全完成的批次操作。
- 權限受限：technician 不可進入此全店列表。

### 7.2 建立／編輯案件

路由：/app/cases/new、/app/cases/[id]/edit  
角色：owner、dispatcher

欄位分組：

1. 客戶：搜尋既有客戶或建立新客戶。
2. 地點：選既有服務地點或新增。
3. 需求：模板、服務類型、標題、說明、來源、優先度。
4. 標的：設備或施工範圍，依模板選填。
5. 下一步：負責人、預計回覆／現勘日期。
6. 附件：客戶提供照片與文件。

規則：

- 優先使用分段單頁，避免過長 modal。
- 自動儲存草稿；離開前若尚未同步需提示。
- 同電話、同地址、近期相似需求顯示重複提示，但不阻擋建立。
- 模板切換時預覽會增加／移除的欄位，既有資料不可靜默刪除。

### 7.3 案件詳情

路由：/app/cases/[id]  
角色：owner、dispatcher；technician 僅可由被指派工單進入受限摘要

頂部摘要：

- 案件標題、編號、客戶、地址、模板。
- 目前階段、責任人、下一步與逾時提示。
- 客戶聯絡、導航與更多選單。

分頁：

1. 總覽：需求摘要、下一步、近期活動、關鍵金額、即將到來工單。
2. 報價：報價版本、接受狀態與追加／追減。
3. 工單：所有到場任務、指派與完成狀態。
4. 現場紀錄：依日期／工單整理照片、檢查表與備註。
5. 收款：應收、已收、到期與付款紀錄。
6. 歷程：不可變的重要事件與通知紀錄。

主要動作依階段變化：

- 新需求：建立報價／安排現勘。
- 待客戶：預覽並追蹤。
- 待排程：建立工單。
- 進行中：查看目前工單。
- 待驗收：送出完工簽認。
- 待收款：建立／提醒付款。
- 已完成：建立回訪／保固。

狀態：

- 資料部分缺失：摘要中顯示「待補資料」清單。
- 其他人剛更新：顯示非阻斷 banner，可重新整理或比較。
- 已封存／取消：維持唯讀並顯示原因；有權限者可重新開啟。
- technican 受限檢視：隱藏成本、毛利、其他工單與非必要客戶資料。
- 關聯項目載入失敗：分頁單獨重試，不使整頁不可用。

### 7.4 案件活動歷程

每筆事件顯示：

- 使用者可理解的動作文字。
- 操作者或系統來源。
- 絕對時間與相對時間。
- 變更前後摘要（需要時）。
- 關聯報價、工單、通知或簽認連結。

一般成員不可刪除歷程。大量低價值技術事件需折疊，重要商業事件預設展開。

## 8. 報價與追加頁面

### 8.1 報價編輯器

路由：/app/cases/[caseId]/quotes/new、/app/quotes/[id]/edit  
角色：owner、dispatcher（依政策送核）

功能：

- 從價目表、產業模板或既有版本複製。
- 區段與項目拖曳排序。
- 項目欄位：名稱、描述、數量、單位、單價、折扣／加價、稅別。
- owner 可見成本、毛利與內部備註；dispatcher 依權限可見。
- 客戶可見與內部欄位有清楚視覺分隔。
- 即時計算未稅、稅額、總額；整數／小數規則一致。
- 報價效期、付款條件、施工範圍、排除項目與備註。
- 儲存草稿、送核、預覽客戶版。

狀態：

- 初始載入：項目 skeleton，固定總額列不可顯示舊資料。
- 自動儲存：顯示「儲存中／已儲存／尚未同步」。
- 計算錯誤：定位到欄位並說明，不只顯示 toast。
- 版本已被送出：編輯頁改唯讀，提供「建立新版本」。
- 另一人正在編輯：顯示姓名與最後更新，不允許靜默覆寫。
- 網路中斷：保留本機草稿，但送核與送出不可離線完成。

### 8.2 報價詳情與核准

路由：/app/quotes/[id]  
角色：owner、dispatcher

功能：

- 顯示版本、狀態、總額、毛利（有權限者）、效期與客戶回應。
- 客戶版預覽不得載入成本欄位。
- owner 可核准、退回修改、撤回、建立新版本。
- dispatcher 可送核、修訂與依政策送出。
- 送出前選擇 LINE 通知模板並預覽。
- 顯示開啟、接受、拒絕與要求聯絡的事件。

狀態：

- 待核准：固定顯示核准／退回動作與變更摘要。
- 已失效：不可接受；可延長時建立新版，不改原版本。
- 已撤回：客戶連結顯示已撤回，內部保留紀錄。
- 通知失敗：報價仍是已送出；顯示補送或複製連結，不回退資料狀態。

### 8.3 追加／追減

路由：/app/cases/[caseId]/change-orders/new、/app/change-orders/[id]  
角色：owner、dispatcher；technician 可提出草稿

功能：

- 指明原因、現場照片、增減項目、金額、工期影響與原報價關聯。
- technician 提出後只能成為草稿，不直接傳給客戶。
- owner／dispatcher 補完內容、送核、預覽並發送。
- 客戶接受後，更新案件已確認總額與必要工單／收款計畫。

狀態：

- 已接受後需再改：建立新追加版本，不覆寫。
- 原工單已完工：仍可關聯，但顯示時間異常警告。

## 15. 共通載入、空白、錯誤與離線狀態

### 15.1 載入

- 初次頁面載入使用符合實際版面的 skeleton，避免布局跳動。
- 按鈕送出保留原文並加進度，不把寬度改變造成誤觸。
- 分頁／篩選切換可保留舊資料並顯示局部載入，不閃成空白。
- 超過 8 秒顯示「仍在處理」與安全取消／稍後查看選項。
- 不用無限 spinner 取代錯誤處理。

### 15.2 空白

空狀態包含：

1. 發生原因或這裡將出現什麼。
2. 對使用者有意義的下一步。
3. 一個主要動作；必要時一個次要說明連結。

區分：

- 真正無資料。
- 篩選後無結果。
- 無權限看到資料。
- 資料尚未同步。
- 服務異常導致無法讀取。

不可把後四種誤顯示為「尚無資料」。

### 15.3 錯誤

- 欄位錯誤就近顯示並保留輸入。
- 區塊錯誤只影響該區塊，可單獨重試。
- 整頁錯誤顯示參考碼、重試與安全返回。
- 權限錯誤顯示可聯絡的 owner，不暴露資源細節。
- 衝突錯誤顯示最新資料與使用者可選動作。
- 伺服器未知結果時，不宣告失敗後直接重送；先查詢是否已完成。

錯誤文案公式：

「沒有完成的動作」＋「資料是否已保存」＋「下一步」。

例如：「照片尚未上傳，但已保留在這支手機。連線恢復後可在『待同步』重試。」

### 15.4 離線與同步

- 頁首或今日頁明確顯示離線、最後同步時間與待同步數量。
- 文字草稿、檢查表、照片上傳佇列可離線保存。
- 報價送出、客戶確認、取消工單、標記付款等不可安全重複的操作必須等待伺服器回應。
- 每個待同步項目有本機 id、建立時間、狀態與重試。
- 登出前若有未同步資料，必須阻擋並說明風險。
- 多裝置衝突不可採最後寫入者靜默覆蓋關鍵商業資料。

## 16. 表單與資料輸入

- 每個輸入都有可見 label；placeholder 不取代 label。
- 必填／選填在欄位名稱旁標示，避免只用星號。
- 手機使用正確鍵盤：電話、數字、email、日期。
- 地址允許手動輸入，不強迫地圖選點。
- 電話儲存標準化，顯示採台灣習慣格式。
- 金額輸入允許先清空再輸入，不自動卡在 0。
- 危險動作用明確動詞，不使用模糊的「確定」。
- 長表單自動儲存；錯誤摘要可點擊跳到欄位。
- modal／sheet 關閉前，未保存變更需確認。

## 17. 照片與檔案

- 客戶與技師上傳前先檢查數量、真實 MIME、大小與可接受格式。
- 手機端生成縮圖與適度壓縮，原始檔是否保留由政策決定。
- 卡片顯示分類、拍攝／上傳時間、上傳者與同步狀態。
- 支援逐張重新分類、補說明、重試與移除未送出照片。
- 已成為報價、追加或完工證據的照片不可由一般角色永久刪除；可標記不公開。
- lightbox 支援上一張／下一張、縮放、下載權限與螢幕閱讀器描述。
- 客戶頁只載入明確設為可公開的照片與衍生檔。

## 18. 響應式與手機優先

### 18.1 斷點策略

- 360–430 px：主要設計基準，單欄、底部導覽、bottom sheet。
- 431–767 px：較寬手機／小平板，維持單欄但增加留白。
- 768–1023 px：平板，可使用雙欄 master-detail。
- 1024 px 以上：桌面側欄、表格、週排程與 contextual panel。

不以固定 max-width 430 px 限制整個 owner／dispatcher 桌面體驗；客戶表單與技師執行頁可維持較窄閱讀寬度。

### 18.2 觸控

- 所有主要觸控目標至少 44 × 44 px，項目間保留足夠間距。
- 不依賴 swipe 才能發現重要動作；swipe 只能是捷徑。
- 拖曳排程在手機需有「移動」替代流程。
- 固定 CTA 不遮住最後一個欄位、鍵盤或系統 safe area。
- 拍照、導航、撥號等現場高頻動作放在拇指可及區域。

## 19. 無障礙

目標：核心旅程符合 WCAG 2.2 AA。

- 所有互動可用鍵盤完成；焦點順序符合視覺順序。
- route change 後將焦點移到頁面標題或主要內容。
- dialog／bottom sheet 開啟時鎖定焦點，關閉後回到觸發元件。
- 圖示按鈕有可理解的 accessible name。
- 表單錯誤以文字與 aria 關聯，live region 宣告送出結果。
- 色彩對比達 AA；狀態、必填、錯誤不只用顏色。
- 支援 200% 文字縮放，不截斷主要操作。
- 尊重 prefers-reduced-motion，重要訊息不依賴動畫。
- skeleton 不被螢幕閱讀器當成真實內容逐項朗讀。
- 拍照圖片若具證據意義，提供分類與簡短描述；純裝飾圖片使用空替代文字。

## 21. 前端資料與狀態管理原則

- Server state 使用具快取、重新驗證與 mutation 狀態的統一資料層。
- 表單草稿與 UI 狀態分開；不把尚未送出的內容直接視為 server truth。
- 所有 mutation 帶 idempotency key 或版本條件，避免重複與覆寫。
- optimistic update 僅用於可回復、低風險操作；報價送出、客戶決定、付款與完工終態需伺服器確認。
- 權限由後端裁決；前端隱藏按鈕只改善 UX，不是安全邊界。
- query key／cache scope 必須包含 organization，切換組織時清除前一組織敏感快取。
- API 回傳公開 DTO 與內部 DTO 分離，禁止客戶頁收到成本或內部備註後再靠 CSS 隱藏。

## 22. 事件追蹤

只追蹤能回答產品假設的事件，且不把電話、地址、照片文字等個資送入分析平台。

必要事件：

- intake_submitted、intake_triaged、first_response_sent。
- quote_created、quote_approved、quote_sent、quote_viewed、quote_decided。
- work_order_scheduled、work_order_started、work_order_completed。
- required_photo_added、upload_failed、offline_item_synced。
- change_order_sent、change_order_decided。
- payment_requested、payment_recorded。
- follow_up_sent、follow_up_converted。

每個事件至少帶 organization 匿名識別、模板、角色、來源、時間與結果；禁止帶客戶姓名、電話、完整地址與公開 token。

## 23. 前端完成定義

一個頁面或流程只有同時符合以下條件才算完成：

- 支援對應角色與權限，未授權 UI 與 API 均拒絕。
- 正常、載入、空白、欄位錯誤、伺服器錯誤、權限、衝突與離線狀態均有設計。
- 360 px 手機、430 px 手機、768 px 平板與 1280 px 桌面完成檢查。
- iOS Safari、Android Chrome、LINE 內建瀏覽器核心流程可用。
- 鍵盤、焦點、螢幕閱讀器名稱、對比與 200% 文字縮放完成檢查。
- 可觀察 loading／mutation／upload／notification 失敗，並提供恢復動作。
- 事件追蹤不含個資。
- 對應的 unit、component、integration 與關鍵 E2E 測試通過。
- 文案、狀態名稱與 [產品規格](./product-spec.md) 一致。
